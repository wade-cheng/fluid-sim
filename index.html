15-418 Final Project: Fluid Simulation

By Wade Cheng, Liam Walker. Project webpage URL at https://wade-cheng.github.io/fluid-sim.

Summary

We plan on implementing a smoothed-particle hydrodynamics parallel fluid simulation. We will compare how the algorithms we implement derive performance on the CPU (testing on our Macbooks) compared to on the GPU (using the Gates clusters).

Challenge

Fluid particles might act on any other fluid particle, which is too many interactions to be efficient.

Every time step, metadata for every particle needs to be updated. Also, particles are only affected by neighbors up to a chosen radius. These two together mean memory locality can be tricky to obtain. The operation doesn’t seem very compute-heavy so our machines may be memory-bound on this workload, and we will have to code around this.

Computations between two particles are symmetric by design, so theoretically only half the number of accesses are necessary here.

Starting resources

We will start the code from scratch. We have some references to start with:

  • Math: Particle-Based Fluid Simulation for Interactive Applications, Müller et al.

    • 2D kernel formulas: SPH Based Shallow Water Simulation, Solenthaler et al.
  • Implementation guide: Implementing SPH in 2D, Schuermann
  • Some optimization ideas: A Parallel SPH Implementation on Multi-Core CPUs, Ihmsen et al.

Goals

Plan to achieve

  • A parallel fluid simulation and analysis of why we were able to get the speedup we did. The speedup analysis could look at problem-constrained scaling, or also time-constrained scaling to see how we can push for more particles while maintaining a set framerate.

Extra goals

  • live demo of the particle simulation (route the parallel fluid simulation into some renderer)

Platform choice

CPU architecture is less affected by complicated, branching code. This can let us find and implement interesting structures that give ability to parallelize more. In constrast, GPU architecture has higher memory bandwidth and threads that may lead to different solutions for computing the same problem efficiently.

For specific platforms, we will investigate our Apple silicon CPUs as well as Gates cluster GPUs.
